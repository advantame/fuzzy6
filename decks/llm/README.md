# LLM — 次の一語から、エージェントまで

LLM を、歴史、基本概念、チャットボット、ツール、つなぐ先、ハーネスの順に見ていき、そのあと 2026 年までの話題（知識を育てる、計算と値段、ハーネスを鍛えて測る、開いたハーネス）に進むデッキです（2026-10-10 着手）。説明を語るより、事実を見やすく並べることを優先します。いまは 10 章 79 本、通して約 22 分です。

4 章から先は、一枚の「ツールの図」を軸にします（下の「ツールの図」）。4 章はツールを抽象的な箱のまま置き、文章の生成とツールがどう噛み合うかを具体的に追います。5 章と 6 章では、同じ図のツールの位置に具体的なものを入れていきます。7 章では、ツールの位置に LLM Wiki のフォルダが入ります。

`npm run dev` のあと http://127.0.0.1:5175/decks/llm/ で開きます。操作は ↑ ↓ で前後のクリップ、← → でクリップの中の止まり、Space で再生と一時停止、I で目次です（全体は `docs/spec.md` §4）。

## 狙い

- 字幕が事実の文を受け持ち、ステージが構造と数字を見せる。字幕の文をステージにそのまま書き写さない。
- 1 本のクリップには 1 つの考えだけを入れる。最後の絵（poster）が、そのまま一枚の図版として読めるようにする。長さは中身で決め、上限は 90 秒。2026-10-10 に作った 78 本は 15〜17 秒にそろえてあるが、この決まりは 2026-10-11 にやめた（下の制作メモ）。
- 仕組みを示すために作った数値やモデルの出力には「例」の札を付ける。事実には出典を付け、ステージの右下に小さく書く。
- 実在するデータで見せられるものは実データを使う。トークンの分割と番号は、実際のトークナイザ（o200k_base）で求めた。

## 見た目の文法

- **地と色**: 枠は墨（#121110）、ステージは紙（#f4f1e9）に 40px 間隔の淡い点。朱（#ff5a1f）は合図に使う一色で、進み、強調、選ばれたものに使う。青は人や入力、緑は成功や確認、赤は誤りや拒否に使う。
- **L 字の二辺**: ステージの下の辺はクリップの進み、左の辺はデッキの中の位置として、朱で満ちていく（`theme.css`）。
- **書体**: 本文は IBM Plex Sans JP、大きな年と数字は IBM Plex Sans Condensed、トークン・コード・番号は IBM Plex Mono。
- **歴史の章の型**: 左の列に朱の札、年、人、論文または製品（`parts.js` の `yearBlock`）。右の列（x = 600 から）に中身を置く。
- **トークンの札**: 6 色の淡い色を順に使う。先頭の空白は小さな点で見せる。
- **rail の題名**: 本文の幅は 236px、42px なので、1 行に 5 字まで、2 行に収める。句の切れ目（`word-break: auto-phrase`）で折れるので、6 字以上の句を作らない。添え書きは 12 字ほどまで。
- **動き**: 入りは outExpo で 0.5〜0.8 秒、ずらしは 0.05〜0.15 秒。線は描き足し、数は数え上げる。最後の 3〜4 秒は読むために止める。語りつきのクリップでは、入り、ずらし、間、強調の速さを歩調（`pace`）から読む。

## ツールの図（4〜6 章の軸）

4 章から先のクリップは、同じ一枚の図の上で動く。部品は `lib/rig.js` にあり、位置は `BASE`（`layout()` が文書と 4 本の通り道を割り出す）。ツールの位置を広げたいクリップは `mix(BASE, 別の配置, p)` で配置ごと動かす。

- **三つの部品**: 左に LLM（墨の四角）、中央にアプリ（パネルの中に白い文書）、右にツール（破線の箱）。6 章ではアプリの名前を「ハーネス」に替える。
- **4 本の通り道**: 読ませる（アプリ → LLM）、続きを書く（LLM → アプリ）、入力（アプリ → ツール）、結果（ツール → アプリ）。いま使っている道は朱に光らせる。
- **文書の印**: システムはパネル色、ユーザーは青、アシスタントは墨、ツールの結果は緑。呼び出しは朱の帯に等幅の文字、結果は緑の帯。印の書き方は説明のための例で、実際の形式はモデルごとに異なる（4-3 で gpt-oss の実例を見せる）。
- **流れの見せ方**: 読ませるときは文書の書いた部分を朱の帯が上から下までなぞり、紙の束が LLM へ飛ぶ。モデルが止まると LLM の上に `stop_reason` の札が出る（`tool_use` は朱、`end_turn` は灰）。入力と結果は、文書の中の位置から通り道を通ってツールへ行き、また文書の中の位置へ戻る（`flow`）。
- **ツールの位置に入れる**: 5〜6 章では、破線の箱が実線になり、中身が抽象的な「ツール」から具体的なもの（検索、シェル、画面、MCP サーバー、子のエージェント）に替わる。箱の上には「ツールの位置」と小さく書く。
- **余白の使い方**: LLM の下（幅 280）に、そのクリップの事実（年、数字、出典の要点）を置く。ツールの下とツールの上は、受け取った呼び出しの札、やりとりの記録、方法の一覧などに使う。

調査は 2 本出した。[research/motion-principles/](../../research/motion-principles/) は、見直しの案を支える研究と反例を調べたもので、規則の案 18 項目がある。[research/voice-terms/](../../research/voice-terms/) は、VOICEVOX のクレジットの表示、合成した音声の配り方、配信用の形式を調べたもので、要点は次のとおり。

この調査を受けて、ボスが同じ日に決めたこと:

- 合成した音声は、公開リポジトリと GitHub Pages に置いてよい。ただし再利用は許諾しない。[voice/README.md](voice/README.md) に注意書きを置いた。
- リポジトリ全体は、当面「All rights reserved」にする（ルートの [LICENSE](../../LICENSE)）。
- そのあと、同じ日のうちに、リポジトリを非公開にし、見せる場所を GitHub Pages から、URL を伝えた人にだけ見せる自前の基盤へ移すと決めた（[docs/publishing.md](../../docs/publishing.md)）。

ボスが 1-1 を聞いて気づいた読み（2026-10-11）。直し方は [research/voicevox-writing/](../../research/voicevox-writing/) で調べた。

- 「ChatGPT」（チャットジーピーティー）は、出だしが高い。低く始めて「ト」で上げ、あとは上げたままにするのが自然。
- 「ツール」は、トーンを下げないほうがよい。長音が弱く聞こえて、「鶴」かと思った。
- 「エージェント」など、ほかは問題なかった。

これを受けて、語彙（[voice/lexicon.js](voice/lexicon.js)、spec §7.3）に二語を入れ、1-1 の 3 文を合成し直した。直したあとの音は、ボスがまだ聞いていない。確かめたのは、合成の手前の数字（`--inspect`）まで。

| 語 | 語彙 | 直す前 | 直したあと |
|---|---|---|---|
| ChatGPT | 平板 | 読みは「チャ'ット…」で頭高 | 「チャ」5.54、「ッ」は無声、「ト」5.91、「ジ」から「ティ」は 5.88〜6.00。低く始まり、「ト」で上がって、高いまま続く。続く「へと」でゆるく下がる |
| ツール | 平板、長音 1.4 倍、優先度 8 | 読みは「ツ'ウルオ」で頭高。ツ 5.98、ウ 5.97、ル 5.80、を 5.52 | ツ 5.76、ウ 5.81、ル 5.79、を 5.77。下がらない |

- 数字はエンジンの高さの値で、大きいほど高い。
- 「ツール」は、優先度が既定の 5 では辞書が効かなかった（エンジンのもとの辞書の「ツール」が勝つ）。8 で効いた。
- 長音の倍率 1.4 は、問題のなかった「エージェント」に合わせた値。「ツール」の「ツ」と「ウ」の母音の長さの合計は 0.152 で、「エー」の 0.188 より 2 割短かった。1.4 倍にすると 0.181 になる。聞いて短ければ、上げる。
- 文 c は 0.02 秒長くなり、クリップは 20.5 秒のまま（20.485 秒）。
- 合成し直した録りには、口の動き（`mouth`）も入った。語りの記録は版 2 になった。
