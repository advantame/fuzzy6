# 保持型のステージ

版 0.2（2026-10-17。4-1 の書き直しと unit テストで見つかった所を書き足した）。クリップを「時刻から、名前の付いた要素の状態を返す関数」として書くための道具（`src/stage/`）の設計と契約です。[improvements.md](improvements.md) の 10 にあたります。engine の契約は [spec.md](spec.md) が正本で、この道具は、その上に載るクリップの書き方の一つです。これまでの書き方（`setup` と `render` で canvas に直接描く）も、そのまま使えます。

## 何を減らすためのものか

これまでのクリップは、時刻 t の絵を、canvas に直接描いていました。描いたものは、描いた瞬間に消えて、名前も位置も残りません。そのため、作る側が手でしていた仕事がありました。

- **前のクリップの最後の絵を写す。** つないで入るクリップ（spec §6.10）は、前のクリップの最後の絵を自分の頭で描き直していました。7 章では、`lib/harness.js` の `final73`、`prepare74`、`G73` のような写しが 3,000 行を超えていました。前のクリップの最後の絵を変えると、次のクリップの写しも直す必要がありました。
- **渡りを手で書く。** 前の絵から自分の絵へ移る動きを、要素ごとに `lerp(…, nar)` と `1 - nar` で書いていました。
- **強調の枠の座標を測る。** 囲む箱を、描いた関数とは別に、手で計算していました。
- **透明度と重ね順の配管。** `ctx.save()`、`globalAlpha *= a`、`ctx.restore()` を、まとまりごとに書いていました。
- **絵を目で読む。** 重なりやはみ出しは、撮った絵を見て探すしかありませんでした。

保持型のステージでは、クリップは描かずに、その時刻の「世界」を返します。描くのはステージです。描いたものに名前と位置が残るので、上の仕事の多くを、道具に任せられます。

## 考え方

- **世界。** ある時刻の絵を作る要素（ノード）の集まりです。ノードには名前（id）があり、描く順に並びます。
- **ノード。** 葉とグループの二種類です。葉は、自分の描き方（種類、kind）と、その引数（props）と、不透明度（a）を持ちます。グループは、ほかのノードをまとめて、不透明度、切り抜き、ずらし、拡大、フィルタを掛けます。
- **場面（scene）。** クリップの本体です。時刻 t を受け取り、その時刻の世界を作ります。毎フレーム、作り直します。時刻の純粋関数（spec §6.1）であることは変わりません。
- **始まりの世界（from）。** つないで入るクリップは、前のクリップの最後の世界から始められます。場面は、その写しを受け取り、変わる所だけを書きます。渡りの間は、ステージが前の世界から自分の世界へ動かします。
- **変数（vars）。** 多くのノードが読む値です（7 章の配置 `G` など）。渡りは、変数も動かします。配置を一つ変えると、それを読むノードがそろって動きます。

## 例

7-4 は、7-3 の最後の絵から始まります。場面の頭は、7-3 の絵から何が変わるかを書くだけです。

```js
import { stage } from '../lib/stage.js';
import * as K from '../lib/kinds.js';
import mcpflow from './mcpflow.js';

export default stage({
  id: 'session', join: 'cut', bridge: 1.0, script: [/* … */],
  from: mcpflow,                                   // 7-3 の最後の世界から始める
  prepare(ctx) { return prepare74(ctx); },         // 時刻によらない配置
  scene(w, f) {
    // 7-3 の絵から 7-4 の絵へ。渡りの間は、ステージがこの変化を動かす
    w.vars.G = G7;                                 // ツールの場所を元の幅に
    w.set('github', { box: NET7, narrow: 0, found: 0 });
    w.drop('plug', 'log', 'notes', 'mcpcard');     // 渡りの間に薄れて消える
    w.set('note.text', { s: NOTE74 });             // 前の文が引いてから、次の文が出る

    // ここからは 7-4 の動き
    w.set('llm', { glow: llmGlow });
    w.add('record', K.record, { rows, a: f.pop('rec') }, { before: 'note.mark' });
    w.add('ring.bar', K.ringBox, { b: 'bar:all', level: shortLit, pad: 6 });   // 帯を、描いた箱で囲む
  },
});
```

これまでの 7-4 は、7-3 の最後の絵を `prepare73` と 7-3 の部品で描き直し、配置を `mix7(G73, G7, nar)` で、消える部品を `1 - nar` で、手で動かしていました。いまは、7-3 の最後の絵を 7-3 の場面が作り、7-4 はそれを受け取ります。7-3 の最後の絵を変えると、7-4 の頭もそのまま変わります。

## 契約

### stage(def)

`src/stage/index.js` の `stage(def)` は、spec §6 のクリップを返します。engine から見ると、ふつうのクリップです。デッキは、紙や方眼などの下地を足す包みを持ちます（LLM デッキは `decks/llm/lib/stage.js`）。

| 項目 | 内容 |
|---|---|
| spec §6 の項目 | `id`、`title`、`script`、`join`、`bridge`、`cast` など。そのまま engine に渡る |
| `scene(w, f)` | 必須。時刻 `f.t` の世界を、`w` に作る |
| `prepare(ctx, stage)` | 任意。時刻によらない配置の計算。返した値は `f.s` で読む |
| `from` | 任意。始まりの世界。保持型のクリップ（その最後の世界）か、関数 `(w, f) => …`（ここで作る世界。前のクリップがこれまでの書き方のとき） |
| `background(ctx)` | 任意。毎フレーム、世界の下に描く |

- `from` があると、場面の `w` は、始まりの世界の写しから始まります。何もしなければ、前の絵がそのまま残ります。作り直したいときは、`w.clear()` してから作ります。
- 渡り（頭より前の時刻）の間は、ステージが、始まりの世界と場面の世界を混ぜます。頭は、最初の文の頭（spec §6.10）です。混ぜる割合は、`inOutCubic` で 0 から 1 へ進みます。

### 世界の操作（w）

| 操作 | 内容 |
|---|---|
| `w.add(id, kind, props, o)` | 葉を足す。`props.a` が不透明度（既定 1）、残りが kind の引数 |
| `w.group(id, props, o)` | グループを足す。props は下の表 |
| `w.set(id, patch, o)` | 変える。`patch.a` は不透明度、残りは props に重ねる |
| `w.drop(...ids)` | 取り除く。グループは中身ごと |
| `w.move(id, o)` | 置き場所を変える |
| `w.has(id)`、`w.get(id)` | あるか、そのノード |
| `w.clear()` | 空にする |
| `w.clone()` | ノード、props、子の並び、vars を一段ずつ写す。props や vars の中の値は共有するので、入れ子を直接書き換えず、値を置き換える |
| `w.vars` | 変数。`w.vars.G = G7` のように書く |

`o` は置き場所と渡りの決まりです。`{ in: グループの id }`、`{ before: id }`、`{ after: id }` のどれかで置き場所を決めます。書かなければ、いちばん上（最後）に足します。`bridge` は、渡りの決まりです（下の「渡り」）。

置き場所を決めるのは `add`、`group`、`move` だけです。`set` の `o` には `bridge` だけを書けます。置き場所を二つ以上書いたとき、グループをその中身の中へ移そうとしたときは、エラーになり、世界は変わりません。

id は、世界の中で一意にします。`~` で終わる id は使えません（渡りが、前の世界の写しに付けます）。

### グループの props

| 項目 | 内容 |
|---|---|
| `a` | 不透明度。0.001 以下なら、中身ごと描かない |
| `filter` | CSS のフィルタ（`'grayscale(1)'` など） |
| `clip` | `{ x, y, w, h }`。この矩形で切り抜く |
| `dx`、`dy` | ずらす |
| `scale`、`origin` | 拡大する。中心は `origin`（`[x, y]`、既定はステージの中央） |

この表の順に効きます。切り抜きは、ずらす前の座標で決まります。

### 種類（kind）

種類は、ノードを描く関数です。`kind(ctx, props, a, env)` の形で、`a` はそのノードの不透明度です。

- 種類は、デッキの部品を呼ぶだけの薄い関数にします。これまでの書き方のクリップが渡していたのと同じ引数で、同じ関数を呼びます。そうすると、画素まで同じ絵になります。LLM デッキの種類は `decks/llm/lib/kinds.js` にあります。クリップだけの種類は、クリップのファイルに置きます。
- 種類は、モジュールの外側で一度だけ作ります。渡りは、同じ id の二つのノードが同じ種類かどうかを、関数が同じかどうかで見ます。
- 不透明度は、ノードの `a` だけで渡します。部品の不透明度（`o.alpha` や、部品の引数の `a`）は props に書かず、種類が `a` を部品に渡します。場面は `w.add('cause', K.tag, { x, y, s, o: { font, fill }, a: causeA })` のように書きます。
- 不透明度を受け取らない部品には、`withAlpha(ctx, a, fn)`（`src/stage/alpha.js`）を使います。1 のときは何もしないので、絵は変わりません。
- 描いた場所がわかる種類は、箱 `{ x, y, w, h }` か、箱を持つ値（カードの行の箱など）を返します。強調の枠と、調べる道具が使います。
- `env` は `{ t, v, box(target), out(id) }` です。`t` はいまの時刻、`v` は世界の変数、`out(id)` はすでに描いたノードの種類が返した値です。

### 強調の枠と箱

`K.ringBox` の `b` には、箱のほかに、ノードの名前を書けます。

- `'bar'` は、ノード `bar` の種類が返した箱（または、その値の `box`）
- `'bar:all'`、`'log:names.0'` は、返した値の中の箱
- 箱の並びも書けて、その全体を一つの枠で囲む

指したノードは、枠より先に描かれている必要があります。ずらしや拡大のあるグループの中のノードも、枠を描く座標に直して返します。

### 時刻の道具（f）

| 名前 | 内容 |
|---|---|
| `f.t`、`f.at(name)`、`f.pace`、`f.cue`、`f.lead`、`f.duration` | 時刻、時間割、歩調（spec §5.1、§6.7） |
| `f.s` | `prepare` が返した値 |
| `f.pop(name, dur, ease)` | 声が `name` に来るとき（`cue.lead` だけ先から）に 0 から 1 へ。既定の長さは `pace.enter` |
| `f.tw(time, dur, ease)`、`f.seg(a, b)` | 時刻から 0 から 1 へ |
| `f.span(a, b, rise, fall)` | a で立ち上がり、b で引く。0 から 1 へ行って 0 へ戻る |
| `f.enter(time, i)` | 並んだ要素の i 番めの入り（kit の `enter`） |
| `f.lit(names, until)` | 声が名前を指すごとの強調の強さ（kit の `focus`） |
| `f.measure(font, s)` | 文字の幅 |
| `f.ctx` | 配置の計算のための context（文字を測る lib の関数に渡す）。場面は、これで描かない |
| `f.answer(id)` | 問題の状態（spec §5.4） |

時刻は、数でも、時間割の名前でも書けます。

### 渡り

渡りの間、ステージは、始まりの世界と場面の世界を、ノードごとに次のように混ぜます。

- **両方にあるノード。** props の中の数と不透明度を、前の値から新しい値へ動かします。配列とオブジェクトは、中の数を一つずつ動かします。動かせない値（文字列、真偽値、長さの違う配列、違う種類）があると、ノードを入れ替えます。入れ替え方は、新しいノードの `bridge` で決めます。
  - `'seq'`（既定）: 前半で前のノードが引き、後半で新しいノードが出る。文が入れ替わるときに、二つが重なって読めなくなるのを避ける
  - `'cross'`: 二つが同時に入れ替わる
  - `'cut'`: 渡りの終わりで入れ替わる
  - `'now'`: 入れ替えない。動かせない値は、はじめから新しい値にする（数は動く）
- **新しい世界にだけあるノード。** 浮かび上がります。`'now'` なら、はじめからそのまま、`'cut'` なら、渡りの終わりに出ます。
- **前の世界にだけあるノード。** もとの位置のまま、薄れて消えます。
- **変数。** 数を動かします。

**グループ。** `bridge` を書かないグループは、`'now'` と同じに扱います。数は動き、切り抜きやフィルタのような動かせない値は、はじめから新しい値になります（7-4 は、7-3 から受け取った文書のグループに、送り始めと同時に切り抜きを足します）。グループに `'seq'`、`'cross'`、`'cut'` を書くと、中身ごと入れ替えます。グループと葉が入れ替わるときの既定は `'seq'` です。

渡りの間に、場面が自分の動きを始めることがあります（7-4 では、文書が渡りの間に送られ始めます）。そうした動きに付いて出るノードは、場面が決めた不透明度のまま出したいので、`bridge: 'now'` を付けます。

### 調べる

ステージは、最後に描いた世界を覚えています。層の `inspect()` は、ノードごとに `{ id, kind, depth, a, box }`（box はステージの座標）を、描いた順に返します。撮影の道具が、絵と一緒に要素の座標を出すときや、重なりの検査（`tools/inspect/overlap.mjs` の `detectOverlap`）に渡すときに使います。

## engine に足したもの

- `stage.timeline(clip)`（spec §6.2、版 0.15）。ほかのクリップの時間割を、いまの歩調で返します。`from` に保持型のクリップを書いたとき、その最後の世界を作るのに使います。engine の振る舞いは、ほかに変わりません。

## 移行の確かめ（2026-10-17）

ボスの指示で、LLM デッキの 4-1（`base`）、7-3（`mcpflow`）、7-4（`session`）を、この書き方で書き直しました。前の書き方の版は `decks/llm/clips/legacy/` に残し、新しい版をデッキに載せました。

確かめ方は、二つの版を engine の層（`src/explorer/layer.js`）で同じ時刻に描き、ステージの 1600 × 900 の画素を一つずつ比べるものです（`tests/fixtures/stage-same/`、`tests/e2e/stage-same.spec.js`）。

| クリップ | 比べたフレーム | 違った画素 |
|---|---|---|
| 4-1 `base` | 60 分の 1 秒ごとに 4,799 枚 | 0 |
| 7-3 `mcpflow` | 60 分の 1 秒ごとに 5,144 枚 | 0 |
| 7-4 `session` | 60 分の 1 秒ごとに 4,726 枚と、渡りの間を 500 分の 1 秒ごとに 551 枚 | 0 |

e2e（`tests/e2e/stage-same.spec.js`）は、三本を 0.1 秒ごとと、すべての止まりで、渡りのある 7-3 と 7-4 は渡りの間を 0.01 秒ごとに比べます（合わせて 2,709 枚、約 50 秒）。止まりの基準（`tests/stops/llm.json`）は、前の版で撮ったものですが、三本とも書き換えずに一致しました。`src/stage/` の unit テストは `tests/stage.test.js` にあります（39 件）。

- 4-1 は、codex（GPT-6 Astra）が、この文書と 7-3、7-4 を手本にして書き直しました。前のクリップからつないで入らないので、`from` を使いません。事前学習の格子と文章、二つのページ、LLM の枠、パラメータ、コンテクストのトークン、確率の行、矢印、問題集、注を、名前の付いたノードに分けました。880 行が 892 行になりました。
- 7-3 は、7-2 がこれまでの書き方のクリップなので、7-2 の最後の絵を、関数で宣言しています（`from: (w, f) => picture(w, f, AT72)`）。渡りの手書きはなくなりました。
- 7-4 は、7-3 の最後の世界から始まります（`from: mcpflow`）。7-3 の配置（`G73`、`TERM73` など）と、7-3 の絵の写しを読まなくなりました。
- 一度だけ合わなかったのは、7-4 の渡りの間の 23 枚でした。文書が渡りの間に送られ始め、それに付いて出る紙の上端のぼかしを、渡りが浮かび上がらせていました。`bridge: 'now'` を付けて、前の版と同じになりました。この経験から、上の「渡り」の最後の段落を書きました。

## わかったことと、まだのこと

- **写しはなくなるが、行数はあまり減らない。** 7-4 は 554 行から 523 行になりました。減ったのは、7-3 の絵を描き直す部分と、手書きの渡りです。残りの多くは、ツールの呼び出しを回す手続き（印が飛ぶ、トークンが書かれる、チップが行き来する）で、これは [improvements.md](improvements.md) の 9（出来事の並びで書く）で減らす部分です。保持型のステージは、その土台になります。出来事は、ノードを足して動かす関数として書けます。
- **画素まで同じにするために残した手書き。** 強調の枠の箱は、前の版と同じ数字にするため、多くを手で書いたままにしました。新しく書くクリップでは、ノードの名前で指せば済みます。
- **種類を作る手間。** デッキの部品を種類として包む必要があります。一度作れば、ほかのクリップでも使えます（7 章の部品は `kinds.js` にそろっています）。
- **ほかのクリップ。** 7-5 から先は、これまでの書き方のままです。7-5 は、`lib/harness.js` の `final74` を写して始まります。7-4 の最後の絵は前の版と画素まで同じなので、つなぎは崩れていません。7-5 から先を書き直すと、`final74` から `final77` までの写しを消せます。
- **文書だけで書けた。** 4-1 を書き直した codex は、この文書と 7-3、7-4 を読んだだけで、画素まで同じ版を作りました。迷った所として挙げたのは、ノードの不透明度（`props.a`）と部品の `o.alpha` の使い分け、`set` で置き場所も変えられるか、グループの渡りの既定、の三つです。どれも、この文書に書き足しました（不透明度は「種類」の節、置き場所は「世界の操作」の節、グループは「渡り」の節）。
- **グループの拡大は縦横同じ倍率だけ。** 4-1 の格子は、縦と横で違う倍率に縮みます。グループでは書けないので、その変形だけを種類の中に残しました。要るクリップが増えたら、グループに `scaleX`、`scaleY` を足します。
- **確かめのために、前の版を残している。** `decks/llm/clips/legacy/` と画素の比べの e2e は、移行が正しいことを示すためのものです。新しい版のクリップの絵を意図して変えたら、前の版とは合わなくなるので、そのときに、そのクリップの前の版と比べの対象を外します。
