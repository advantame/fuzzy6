## 制作の検査道具（2026-10-17）

`docs/improvements.md` の提案 1・3・6 を実装した。クリップと engine の振る舞いは変えていない。`check` と `stops` は dev サーバが必要で、`FUZZY6_URL` の既定は `http://127.0.0.1:5175`。別の作業ツリーでは、例えば `FUZZY6_URL=http://127.0.0.1:8080 npm run check -- llm session` と指定する。unit の `script-plugin.test.js` も 8080 を使うので、このポートの自分の dev サーバは unit の前に止める。

- `npm run check -- llm session`: 長さ、文・静止点の数、字幕の各ページ、同じ話者の「の。」、録りのカナ、読み違いが起きやすい型を出す。字幕は立ち絵画像の有無によらず、立ち絵ありの幅で測る。条件付きの文も、その条件を満たす答えで字幕を調べる。録りの状態は合成ツールの `takeStatus` で判定する。字幕の行数違いか隣接する「の。」で終了コード 1、注意だけなら 0。`--deck` は本線の章別・合計時間と、別に深掘りの時間を出す。
- `npm run tok -- 'セッションを手元のファイルに残して'`: o200k_base、11 トークン。切れ目は `セ | ッション | を | 手 | 元 | の | ファ | イル | に | 残 | して`。js-tiktoken は 1.0.21 に固定した。UTF-8 の文字の途中で切れるトークンは、単独で表示すると置換文字になるため、ID も出す。特殊トークンの綴りも通常の文字列として数える。
- `npm run pngdiff -- a.png b.png`: RGB を不透明な RGBA に揃えて画素を比べる。8 bit RGB/RGBA、インターレースなしに限る。PNG の CRC と走査線も検証する。一致は終了コード 0、不一致は 1、未対応・壊れた画像は 2。session の 73.930 秒と 78.742 秒のステージ画像では、18,772 画素、箱 `{x:135,y:56,width:455,height:260}` の違いだった。

### 止まりの基準

`npm run stops -- [deck] [clipId …]` は比較だけ、`--update` は指定したクリップだけを更新する。クリップを省いた更新では、デッキから削除したクリップの基準も除く。デッキも省くと `decks/*/deck.js` のある全デッキが対象。Chromium の版が違う状態では、クリップだけの更新はできない。

基準は `tests/stops/<deck>.json`。キーは `001@1.000:line:a` のように番号・時刻・種類・文を含む。深掘りを含む全止まりを記録し、問題は答えなしの既定状態で撮る。`&clean`、viewport 1600×900、deviceScaleFactor 1 を使い、ステージの実寸・canvas の描画バッファ・PNG の寸法を検査する。枠、字幕、立ち絵は含めず、`.mx-stage` の PNG を復号した RGBA の SHA-256 を比較する。PNG の圧縮方式の違いはハッシュに影響しない。DOM を使うステージも撮れる。

初回の基準は Chromium 151.0.7922.34（固定した Playwright の chromium-1234）で作った。全フレームを二度描いて撮り、一致を確かめた。初回作成は320.9秒。別のブラウザプロセスで行うe2eでも一致した。

| デッキ | クリップ（深掘り込み） | 止まり |
|---|---:|---:|
| anglesum | 20 | 183 |
| demo | 12 | 41 |
| llm | 86 | 943 |
| trig | 11 | 113 |
| 合計 | 129 | 1,280 |

e2e はデッキごとの4試験を並列に走らせる。不一致・増減は短い識別子とハッシュの先頭12字で報告する。実際のPNGは `test-results/stop-differences/` に、全workerを通して最大20枚まで保存する（atomicなslotファイルで共有）。CLIの比較は `test-results/stops/` に最大20枚まで保存する。基準の更新は明示した場合だけで、不一致を見て自動更新しない。Chromiumだけでなく、OS・書体のラスタライズ環境が変わった場合も画像を確認して更新する。

### 重なりの診断

`npm run check -- llm session --overlap --stops` は全止まり、`--overlap --at 1 78.742` は指定時刻を調べる。発見だけでは終了コード0、`--strict` で1にする。通常の字幕・読み検査とは別の診断モード。

`tools/inspect/canvas.mjs` は `addInitScript` でcanvas APIを包み、指定した同期描画の1フレームだけを記録する。描画した文字の実際の箱と変換、矩形の塗り・線・不透明度を集め、矩形のclipを適用する。`tools/inspect/overlap.mjs` の `detectOverlap(boxes)` はDOMに依存せず、将来の保持型ステージも同じ `{kind,x,y,w,h,alpha,text?,paint?,edge?,order?}` の配列を渡せる。`edge` はclip前の縁、座標は1600×900の論理座標。

LLM の `base`・`mcpflow`・`session`、三角関数の `define`・`ladder` で全止まりを検査し、次を除外した。

- 同じ文字を同じ場所に重ねた色の描画、不透明度0.5未満、後から不透明な矩形で完全に隠した要素。
- 相手を含む背景・パネル、文字が中に収まる小さな札や囲み。文字が縁をまたぐ場合は残す。
- 大きなパネルの縁の中央線に正確に置いた、小さな端子・タブとその文字。上限は64×32、パネル面積の5%。端子に見える大きさだけでは除外しない。
- 同じ縁をfillとstrokeで描いた場合の重複した報告。

検査結果は `base` 16件、`mcpflow` 57件、`session` 58件（全止まりの合計）。`define` と `ladder` は0件。`base` の55.429秒では質問と答えが二重に描かれているのを実画像でも確認した。`session` の最後では「認証の設定は省略」とパネルの縁、「保存しない設定…」とコマンド札の縁が2px以内にある2件を残した。ここは注意の対象だが、直すかどうかは制作側で判断する。

限界: 角丸・回転した要素は軸に平行な箱で近似する。複雑なclipは注意を出して近似し、Path2D、画像、DOMの文字、影、部分的に覆われた画素は解析しない。近接の注意だけで見た目の合否は決めない。

資源の上限: ブラウザ操作15秒、check/stops全体540秒（外側の監督プロセスが子プロセス群を終了）、tok/pngdiff全体30秒。1フレーム2,000箱、1フレーム200報告、1回4,000出力行・1MiB。PNGは1枚32MiB・800万画素までで、zlibの展開量も寸法で制限する。1フレームの報告は200件で表示を打ち切り、総数を出す。箱の数や総出力など、それ以外の上限に達した検査は成功扱いにせず終了コード2とし、対象を絞り直す。

最終検証: unit は33ファイル・2,578件成功（6.25秒）、e2e は155件成功（実測118.88秒）、build は成功（Vite計測0.681秒）。追加前の146件のe2eは39.8秒で、全体の増分は約79秒。10分のglobalTimeout内に収まる。既存試験の初回起動で2件が5秒待ちを超えたが、既存146件だけの再実行と、追加後の全体実行では通った。初回のunitは8080の競合を解消してから全件通した。
